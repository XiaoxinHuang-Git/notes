## 11-07 PDO 关闭模拟预处理后，三个行为会变

**结论**：生产环境把 `PDO::ATTR_EMULATE_PREPARES` 设为 `false`，但改造时要注意占位符复用、LIMIT 绑定、返回类型三处差异。

**默认值**：PDO 连接 MySQL 时该项默认为 `true`。此时参数由 PDO 在客户端转义后拼进 SQL，本质仍是字符串拼接，只是转义交给了驱动。

```php
$pdo = new PDO($dsn, $user, $pass, [
    PDO::ATTR_ERRMODE          => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_EMULATE_PREPARES => false,   // 走 MySQL 服务端预处理
]);

// 查看当前值
var_dump($pdo->getAttribute(PDO::ATTR_EMULATE_PREPARES));
```

**差异一：同名占位符不能复用**

```php
// emulate = true：正常
// emulate = false：SQLSTATE[HY093] Invalid parameter number
$stmt = $pdo->prepare('SELECT * FROM orders WHERE buyer_id = :uid OR seller_id = :uid');
$stmt->execute([':uid' => 1001]);
```

原生协议只支持位置参数，PDO 需要把命名参数重写成 `?`，同名参数会超出绑定数量。改成两个参数即可：

```php
$stmt = $pdo->prepare('SELECT * FROM orders WHERE buyer_id = :buyer OR seller_id = :seller');
$stmt->execute([':buyer' => 1001, ':seller' => 1001]);
```

**差异二：LIMIT 必须显式按整数绑定**

```php
// emulate = true 时若按字符串绑定，最终拼成 LIMIT '10'，语法报错
$stmt = $pdo->prepare('SELECT * FROM orders ORDER BY id DESC LIMIT :n');
$stmt->bindValue(':n', 10, PDO::PARAM_INT);
$stmt->execute();
```

`execute([10])` 在模拟模式下会按字符串处理，这里必须用 `bindValue` 指定 `PARAM_INT`。

**差异三：返回类型不同**

开启 `mysqlnd` 且关闭模拟预处理时，整型列返回 `int`、浮点列返回 `float`；模拟模式下所有列都是字符串。依赖严格类型比较的代码（如 `===`）要提前确认。

**排查建议**：连接串上显式写死这个参数，不要依赖 php.ini 默认值——不同环境的默认值可能不一致，问题只在生产暴露。

## 11-07 proxy_pass 带不带尾斜杠，转发路径完全不同

**结论**：`proxy_pass` 后面写不写 URI（含末尾那个 `/`），决定了 nginx 是原样透传请求路径，还是把 location 前缀替换掉。排查上游 404 时先看这一处。

**原因**：nginx 文档的表述是——`proxy_pass` 指定了 URI 时，请求 URI 中与 location 匹配的那部分会被替换成该 URI；没有指定 URI 时，请求 URI 原样转发给上游。

```nginx
# 情况一：只写 host:port，没有 URI，原样透传
location /api/ {
    proxy_pass http://127.0.0.1:8080;
}
# /api/users -> http://127.0.0.1:8080/api/users

# 情况二：带一个 /，相当于剥掉 location 前缀
location /api/ {
    proxy_pass http://127.0.0.1:8080/;
}
# /api/users -> http://127.0.0.1:8080/users
```

**最容易踩的坑**：location 写 `/api/`，`proxy_pass` 却写成不带尾斜杠的 `http://127.0.0.1:8080/api`。此时匹配到的 `/api/` 被替换成 `/api`，剩下的 `users` 直接贴上去：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080/api;   # 少了一个斜杠
}
# /api/users -> http://127.0.0.1:8080/apiusers
```

表现是连接正常、上游返回 404，上游 access log 里的 URI 变成 `/apiusers`。规则很简单：两边都带斜杠，或者两边都不带，不要混着写。

**正则 location 不能带 URI**：下面这种写法启动时直接失败：

```nginx
location ~ ^/api/(.*)$ {
    proxy_pass http://127.0.0.1:8080/$1;
}
```

报错信息是 `"proxy_pass" cannot have URI part in location given by regular expression`。需要改路径就先用 `rewrite ... break` 把 URI 改好，`proxy_pass` 里只留 `http://127.0.0.1:8080`。

**关联配置**：上游返回 302 且 `Location` 里带内网地址时，浏览器的跳转会指向错误地址。保持默认的 `proxy_redirect default;` 会按 `proxy_pass` 里的上游地址做替换，但它只在 `proxy_pass` 不带 URI 时生效；带 URI 的场景要显式写 `proxy_redirect http://127.0.0.1:8080/ /;`。

**验证方式**：改完先 `nginx -t` 确认语法，再 `curl -i http://127.0.0.1/api/users`，对照上游 access log 里的真实 URI，比在浏览器里猜快得多。
